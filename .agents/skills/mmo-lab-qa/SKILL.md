# Senior QA Methodology: Комплексное тестирование лабораторных работ по машинному обучению (ММО)

Настоящий регламент определяет строгие стандарты качества, критерии приемки (Acceptance Criteria) и полный цикл сквозного тестирования (End-to-End QA Lifecycle) для студенческих и прикладных проектов машинного обучения, разведочного анализа данных (EDA), подготовки данных, Jupyter Notebooks и академической отчетности.

---

## 1. Фазы цикла тестирования (Testing Lifecycle)

1. **Static Analysis & Requirements Traceability (RTM):**
   - Сопоставление ТЗ лабораторной работы со всеми компонентами реализации (100% покрытие требований).
   - Линтинг кода (PEP 8, flake8/ruff, типизация, исключение мертвого кода и неиспользуемых импортов).

2. **Data Pipeline & Statistical Testing (Data Integrity QA):**
   - Проверка структуры и типов данных датасета (до и после обработки).
   - Тестирование пропусков: контроль полноты устранения (0 residual NaNs), обоснованность стратегии импутации (мода для категориальных, медиана/среднее для числовых), исключение утечки данных (Data Leakage).
   - Тестирование выбросов: математическая проверка правила Тьюки ($1.5 \times \text{IQR}$) или правила 3-сигма, проверка граничных условий при винзоризации (clipping), валидация физического смысла признаков (например, проценты $\le 100$, время $\ge 0$).
   - Тестирование Feature Engineering: отсутствие деления на ноль (`np.nan` / `np.inf`), исключение коллинеарности и переобучения, адекватность формул и округления.
   - Тестирование кодирования: отсутствие фиктивной ловушки дамми-переменных (`drop_first=True` в One-Hot Encoding), корректность бинаризации.
   - Тестирование масштабирования: валидация формул `StandardScaler` ($\mu=0, \sigma=1$) и `MinMaxScaler` ($[\min, \max] = [0, 1]$), раздельное масштабирование признаков и целевой переменной.

3. **Runtime & Reproducibility Testing (Dynamic QA):**
   - Запуск всех скриптов пайплайна в чистом окружении с проверкой кода возврата (`exit code 0`).
   - Идемпотентность и детерминированность: фиксация `random_state` / `seed`, совпадение контрольных сумм или метрик при повторном прогоне.
   - Верификация Jupyter Notebook: последовательный сквозной запуск ячеек от 1 до N, отсутствие прерванных ячеек (`Kernel Crash`, `Traceback`), сохранение результатов и визуализаций в структуре `.ipynb`.

4. **Visual & Graphical Quality Assurance (Visual QA):**
   - Разрешение и четкость: экспорт графиков строго в высоком разрешении (DPI $\ge 300$).
   - Геометрия холста и `bounding box`: полное отображение всех подписей осей, названий признаков, меток делений, легенд и общих заголовков (`bbox_inches='tight'`).
   - Читаемость меток: наклон под 45° при большом числе категорий/признаков, выравнивание `ha='right'`.
   - Семантическая цветовая палитра: единый стиль графиков (Seaborn / Matplotlib), цветовое кодирование состояний (красный — дефекты/выбросы/пропуски, зеленый — нормализованные/очищенные данные).
   - Симметрия сеток: запрет пустых неиспользуемых слотов в многопанельных сетках (заполнение аналитическими карточками сводных метрик).

5. **Compliance & Academic Standards Audit (СТП 01-2017):**
   - Поля страницы: Левое — 30 мм, Правое — 15 мм, Верхнее — 20 мм, Нижнее — 20 мм.
   - Шрифт: Times New Roman, кегль 14 pt, полуторный межстрочный интервал (1.5), абзацный отступ 1.25 см.
   - Титульный лист: стандарт БГУИР, отсутствие жирного начертания в блоках исполнителя и преподавателя.
   - Листинги кода: моноширинный шрифт (Courier New / Consolas), кегль 9–10 pt, без рамки, одинарный интервал.
   - Подрисуночные подписи: по центру страницы, формат «Рисунок X.Y – Название рисунка».
   - Таблицы: по центру, заголовок над таблицей «Таблица X.Y – Название таблицы».
   - Кросс-форматная синхронизация: DOCX $\equiv$ PDF $\equiv$ LaTeX $\equiv$ Jupyter Notebook.

6. **Release Packaging & VCS Hygiene:**
   - Полная комплектность итогового ZIP-архива для сдачи.
   - Проверка `.gitignore`: отсутствие служебных файлов (`.pyc`, `__pycache__`, `.ipynb_checkpoints`, `.tmp`).
   - Синхронизация с удаленным репозиторием GitHub (ветка `main`, clean working tree).

## 2. Чек-лист предрелизной приемки (Release Gate Checklist)

Перед утверждением работы Senior QA Engineer обязан проставить статус по каждому пункту:

- [ ] **REQ-01**: Все пункты задания выполнены в полном объеме.
- [ ] **DATA-01**: Пропущенные значения полностью устранены (проверено программно и графически).
- [ ] **DATA-02**: Выбросы и аномалии выявлены, отфильтрованы/винзоризированы, физический диапазон корректен.
- [ ] **DATA-03**: Новые признаки (Feature Engineering $\ge 2$) обоснованы предметной областью, вычислены без ошибок деления на 0.
- [ ] **DATA-04**: Категориальные признаки закодированы (бинарные 0/1, OHE с `drop_first=True`).
- [ ] **DATA-05**: Масштабирование выполнено корректно (сравнение StandardScaler и MinMaxScaler).
- [ ] **PIPE-01**: Скрипты генерации исполняются с кодом 0 без предупреждений и ошибок.
- [ ] **NOTE-01**: Jupyter Notebook полностью выполнен, ячейки пронумерованы по порядку 1..N.
- [ ] **VIS-01**: Графики 300 DPI, нет наложения текста, нет обрезанных названий колонок.
- [ ] **DOC-01**: Отчет в DOCX и PDF оформлен строго по СТП 01-2017 БГУИР.
- [ ] **SYNC-01**: Числовые данные в отчете совпадают с выводами скриптов и ноутбука.
- [ ] **ARCH-01**: ZIP-архив сформирован, распаковывается без ошибок, содержит все артефакты.
- [ ] **GIT-01**: Все актуальные файлы зафиксированы в git и отправлены в GitHub.
